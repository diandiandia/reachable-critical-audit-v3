# Kernel 零硬件实证通道手册

> 面向无物理外设/无硬件射频环境的内核缺陷实证——四条通道全部实测成立。
> 每条含适用面、观测方法、陷阱注记。来源: K6 批次教训 #12、K7 批次教训 #10、
> K8 批次闭环决策（R5 responder 通道）（source_lessons 追溯, 2026-09）。

## 1. 纯软件 USB 控制器通道

- **形态**: 内核树内 dummy 类 host controller driver（出树构建交付 Image 或
  内核模块）+ gadget 函数驱动, 端点数据在软件层环回——无需任何 USB 硬件。
- **适用面**: gadget/设备侧 USB 解析面（描述符、EP0 控制请求、批量传输路径）。
- **观测**: dmesg 栈痕迹 / RSS 峰值 / exit code / 注入触发计数（对照基线）。
- **陷阱**: 出树模块须与目标内核同工具链编译; 模块版本魔数不匹配时装载返回
  ENOEXEC（部分内核对「忽略版本魔数」装载标志的组合不生效, 换装载器
  或改由构建系统直接链入镜像）。

## 2. 虚拟 USB 存储控制器通道

- **形态**: 虚拟机虚拟 USB 控制器 + 内核 USB 大容量存储（mass storage）协议栈——虚拟硬件层即注入面, host 侧协议响应可完全控制。
- **适用面**: host/存储设备解析面（SCSI 命令、批量传输、容量/几何声明）。
- **观测**: 同上四条; 磁盘镜像字节流即攻击输入, 单变量可控。

## 3. 远程协议模拟控制器通道

- **形态**: 内核侧模拟 controller driver 绑定**真实目标协议核**——协议栈在
  树内, 控制器实现可自定义（自定义出树 .ko 或复用树内模拟驱动）。目标协议
  帧由用户态程序任意构造注入。
- **适用面**: 无线/短距协议核心族（帧解析、重装、状态机转换路径）。
- **观测**: 同上四条; 帧构造脚本与注入接口作为 harness 落盘。

## 4. 用户态 RPC responder 通道

- **形态**: 恶意服务端场景——服务端实现嵌入用户态探针进程（标准库/通用 RPC
  框架实现服务端语义）, 客户端走**真实内核协议栈**发起挂载/请求, 挂载链与
  元数据链全通。
- **适用面**: 客户端侧协议解析面（XDR 解码、分页边界、重传/重装路径）。
- **观测**: 挂载链是否建立、响应字节流注入点、客户端 exit code/RSS/dmesg。
- **陷阱**: responder 只实现协议最小语义即可, 不必完整服务端实现——最小
  响应集能驱动目标代码路径即成立。

## 共用判据

- **单变量纪律**: 一次只变一个协议字段; 基线（合法值）与攻击值配对跑。
- **实证据链**: 观测前快照计数器（cgroup memory.events 等）/先落盘日志文件,
  事后补记失去场景。
- **fidelity 标注**: 上述通道均为 equivalent 档（模拟/虚拟环境）——申报材料
  按档位标注, 不混级申报; real_target 环境可及时对 equivalent 结论抽验。
