## 2. 设计偏见

**检查方法**：每项修复是否把「本批我的编排便利/agent 行为偏差」错当 skill 义务。

- D-6/D-8 组：agent 写非 canonical 字段是 agent 行为偏差，但 skill 义务≠「强制
  agent 听话」，而是「机械层容忍 + 任务书明示 canonical 名」——容忍契约（D-6）
  与指引（D-8）都不惩罚 agent 漂移，不把 agent 缺陷当 skill 硬义务。✓ 无偏见
- D-5：截断设计原意为「关键段保留」，本批修的是「判定函数漏识别关键段形态」，
  修法保持截断语义不变（不改为全文透传——全文透传会牺牲 prompt 预算控制，
  是另一种偏见）。✓
- D-3：不自动改写非法 verdict（D-4 先例「误猜风险>收益」），只给建议映射——
  与 v3.14 评估裁决一致，未因本批两次手工归一化便利而加自动改写。✓
- D-7：不把「消费者假定 dict」判为生产者缺陷——生产者字符串形态是设计形态
  （docstring 明示），修消费者。✓ 无归因偏见
- D-12：义务落点是「verifier 显式列未测平台」（供复活波定向补测），不是
  「复活者必须补测」——补测是 freetype 复活者的自发增值行为，不强制化。✓

**结论：无设计偏见违规。** 反向发现一处流程级偏见（见四缺陷评估结论的「修复
流程缺陷」）：v3.14 批的三处热修复（D-5/D-6/D-7 热修部分）未同步补测试——
「热修复不配测试」是修复流程的偏见，D-5~D-7 的正式化即纠偏。
