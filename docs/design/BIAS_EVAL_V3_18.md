# BIAS EVAL V3.18 — 四缺陷评估（2026-09-01）

## ① 盲目带入历史审计信息

- **案例支撑**：本会话战略评估（知识资产 0%、账本 111/192、ERROR-HANDLING/
  NUMERIC 空壳族）+ 仓内证据（L2 签名 16 语言语义、清单 source_lessons、
  SKILL.md 机制形态实录）——设计件逐格要求 source_lessons 指向仓内证据，
  禁止凭 LLM 通用知识臆造种格（种格诚实纪律 = 本版核心纪律）。
- **去项目化**：cell 正文（patterns/sinks/pitfalls）机制形态零项目名；
  项目归属只进 source_lessons（清单库先例：nghttp2/s2n-tls 合法追溯）。
  机器守卫：test_v318 内 DEPROJECT_BLACKLIST 扫描种格正文。

## ② 设计偏见

- **编排便利 ≠ skill 义务**：矩阵读取是提示级条款（无强制义务）；回填是
  验收判据条款（非 gate、非 R6 强制步骤）——不复制 target_kind 门禁形态。
- **不自动改写**：无自动绑定（binder 零改动）；cells_for 只读；回填由
  主代理手工两段式执行（两段式 = 第一原则既定纪律）。
- **修法层级**：知识缺口以数据资产承载，不升级为任务书义务（agent 行为
  偏差 ≠ skill 硬义务，v3.15 D-6/D-8 先例）。

## ③ 死代码

- **消费者清单**：language_issue_matrix.py 每个函数——load（cells_for/
  stats 内部）、cells_for（CLI cells + SKILL.md R2 条款消费）、stats
  （CLI stats + 验收盘点）、_lang_alias（cells_for 内部）——逐函数一消费者。
- pending 格 = 有意占位（stats 可见、零注入），非死数据——回填纪律条款
  是它的消费者路径。

## ④ 过设计

- **无新门禁名、无新阶段、无新强制义务、binder 零改动**——零机制版本。
- **义务入库三问**：
  - R2 矩阵提示条款（触发=主代理执行 cells 命令，提示级；消费者=R2 假设
    生成；裁掉丢 D-2 消费端——矩阵变死资产）；
  - 回填验收判据条款（触发=验收收官，判据级非 gate；消费者=矩阵积累闭环；
    裁掉丢 D-3——知识仍不积累）；
  - 不建「矩阵覆盖率 gate」（无案例支撑，账本 gate ⑦ 已有覆盖语义，
    重复建 = 义务棘轮）。
- **明确不做**：per-language Top10 全量预填（无仓内证据的格 pending——
  192 格全种 = 知识臆造）、binder 按矩阵自动绑定（requires_lang 语义已
  存在但矩阵绑定无失误案例支撑）、TOOLING 不前进的变体（v3.13 内容版
  先例：内容版沿惯例前进版本号）。
