# 模型能力利用评估: 现有设计可否优化 (v3.37 评估件)

> 2026-09-09。案例支撑全部来自 Caddy 验收实录 (lessons.md + 波次/实证产物)。
> 本文是评估件, 不是设计五件套——候选优化须经义务入库三问与四缺陷审查
> 后才能进入下版本 C0。

## 一、结论先行

现有设计对模型能力的利用**不对称**: "生成端"(测绘/假设/验证)利用充分,
"对抗端"与"实证端"的耦合不足——而 Caddy 验收证明, **发现的增量价值几乎全部
来自对抗与实证, 而非生成量** (48 假设 → 11 候选 → 5 REACHABLE 中 2 条靠实证
拦截降级/证伪, 2 条 R4 独立发现靠自主实证, H4 推翻 drop 论据靠深度对抗推理)。
优化方向不是"让模型多生成", 而是"让模型的对抗推理与执行能力更早、更结构化
地介入"。

## 二、模型能力轴 × 现状利用度 (Caddy 实证)

| 能力轴 | 现状机制 | Caddy 实证 | 利用度 |
|---|---|---|---|
| 广度并行 | 4 域测绘/4 候选波次/7 假说并行 | 70 面 26+20+12+12, 质量高 | 高 |
| 深度对抗推理 | N=2 证伪视角差异化/fixminer 模板/对抗枚举条款 | **H4 独立推翻 HYP-045 drop 论据** (root 无交互静默安装); refuter #1 自写 httptest 证 h2 面 | 中——存在但非结构化 |
| 自主实证 | harness 模板 + real_target 全开 | **H1 自主测 923MB/765MB RSS; refuter 自写 h2 实验; H2 独立复证 10B key** | 中——能力已证, 未义务化 |
| 外部知识 | verifier 步骤 1.5 upstream 检索 (git log -S/CVE/master 核对) | **CAND-001 上游 master 核对证明缺口仍开放; CAND-005 靠修复 commit 祖先对账判 UNREACHABLE** | 中——后置到 R3, 且仅 verifier 任务书条款 |
| 结构化消费 | schema 强校验/机械重算/保真校验/铁律 | 拦截行号漂移/文件漂移/字段形态 | 高 |
| 批内学习 | 无 (教训只在收官复盘入下版本) | — | 零 |

模型失灵实证 (同样宝贵): cap-vs-len 语言语义错误 (CAND-011)、量级前提幻觉
(CAND-002)、文件/行号漂移 (PROC-007)——**均被实证或独立复核拦截, 说明防线
有效但拦截点偏后** (R5 才拦下 CAND-011, 已消耗一次候选验证+证伪轮次)。

## 三、优化候选清单 (义务三问初评)

### A. 同族不一致防御假设模板 (CAND-001 形态, 建议入库)

- 机制: "同代码库内同功能族的不同端点/路径防御不一致" 是通用缺陷形态——
  本批最高价值发现 (/config 有 100MB cap, /load//adapt 没有) 即此形态。
  入库形态: 清单条目 (R3 verifier 步骤: 同族端点守卫对比枚举) + R2 假设模板
  (hints 装载后对同族 sink 做"防御矩阵"对比)。
- 三问: ①触发条件 = 同族多端点功能面 (无条件类, 通用); ②消费者 = verifier
  清单绑定 + 假设生成提示; ③裁掉丢什么 = CAND-001 形态的发现通道。
- 裁决: **P3 入库** (提示级清单 + 假设模板), 不建新门禁。

### B. Verifier 自证伪轮机制化 (建议入库, 提示级)

- 机制: verifier 产出附 `self_refutations` 数组 (≥2 条, 对自己的 REACHABLE
  判定做对抗攻击——"什么前提若为假则本判定翻转")。证伪者任务书注入 verifier
  的自证伪清单, 针对性攻击 (而非从零找角度)。
- 依据: CAND-002 的前提幻觉在证伪轮 1/2 才被指出——若 verifier 自证伪
  已在场, 该幻觉可能被自我暴露, 证伪轮可更早聚焦。
- 三问: ①触发条件 = REACHABLE 判定 (提示级); ②消费者 = 证伪者任务书注入
  (Mode W refutation script 消费); ③裁掉丢什么 = 证伪深度的第一层。
- 裁决: **P2 入库** (schema 可选字段 + 任务书条款; 不强制——空数组容忍)。

### C. Upstream/公开面检索前置到 R2 (建议入库, 提示级)

- 机制: R2 假设生成前跑公开面关联 (CVE/issue/上游 master 核对), 而非 R3
  verifier 步骤 1.5——(a) 已知 CVE 关联的假设直接标注定级依据; (b) "上游已修"
  的假设形态直接降级或改口径 (CAND-005 若 R2 已对账可省整条验证)。
- 三问: ①触发条件 = 网络可用 (WebFetch/WebSearch 可用即跑, 不可用跳过);
  ②消费者 = 假设生成输入 + 筛选判据; ③裁掉丢什么 = CAND-005 形态的重复
  验证成本 + CAND-001 的上游仍开放佐证。
- 裁决: **P3 入库** (R2 条款追加一段; verifier 步骤 1.5 保留为复核)。

### D. 可实证候选的 verifier 实证义务 (建议入库, 提示级)

- 机制: 目标可构建且 claim 属实证类时, verifier 任务书附加条款——"本候选
  存在低成本实证路径时 (构建 + 最小复现), 建议实测并附数字; 无实证环境须
  记录 blocker 证据"。H1/H4 已证明模型自发实证能力, 义务化使其稳定发生。
- 三问: ①触发条件 = empirical_feasibility 全开且 claim 属实证集 (提示级,
  非强制——无环境即记录); ②消费者 = 分级 (实测数字 → 回填依据) + 证伪者
  (以实测为攻击面); ③裁掉丢什么 = 静态声称到 R5 才被拦截的轮次浪费
  (CAND-011 形态)。
- 裁决: **P3 入库** (verifier 任务书条款, 提示级)。

### E. 现场构造 harness 回收条款 (已有隐含机制, 建议显式化)

- 机制: 收官复盘把本批现场构造的实证程序评审去项目化入库 (paired_control_probe
  即此路径的产物)。当前 R5 只写"现场构造", 未写回收义务。
- 裁决: **P4 条款一行** (SKILL.md R5 补"收官复盘: 现场构造 harness 通用化
  价值评审")。

### F. 动态证伪者数量 (裁除)

- 机制: 高价值 REACHABLE 加第 3 证伪者。编排复杂度 + 无先例支撑 (N=2
  多数决已有三次实战拦截背书), 收益未证实。
- 裁决: **裁除** (过设计防线)。

### G. 批内教训注入 (裁除)

- 机制: 波次 N 教训注入波次 N+1 任务书。锚定偏差风险 (已知证伪形态会引导
  后续 verifier 预设结论), 违背独立复核的独立性前提。
- 裁决: **裁除** (独立性优先)。

## 四、优先级路线

1. **下一版本 (v3.38)**: A + B + C + D + E (全为提示级/清单级, 零新门禁,
   零强制义务——符合义务三问与过设计防线)。
2. 验收载体: 需一个"同族多端点 + 可构建 + 有公开 CVE 史"的项目才能同时
   验证 A/C/D 三机制 (形态参照 Caddy 但语言可换)。
3. 测量判据: 下批验收对比指标——(a) 假设→候选的发现类多样性 (A 是否产出
   新形态假设); (b) 证伪轮拦截时点提前 (B 是否让前提幻觉在 verifier 层
   自暴露); (c) R3 候选的实证覆盖率 (D 是否提高静态声称的实测比例)。

## 五、不变式重申

本文全部候选为**提示级/清单级**, 不触碰: 六门禁判据、队列数据模型、阶段
骨架、N=2 多数决、铁律。模型能力增强不改变"证据裁决"铁律——模型输出始终
是被验证对象, 机制不变。
