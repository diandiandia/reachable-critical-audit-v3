# REQ_V3_10_2 — 系统需求（v3.10.2 缺陷修复）

> 对应设计文档：SYSTEM_DESIGN_V3_10_2.md。需求编号 REQ-V3.10.2-xxx。
> 每条需求含：语义 / 触发条件 / 消费者 / 案例支撑（三问已过，见设计文档 §3）。
> 本版不改变阶段骨架、六门禁判据语义、队列数据模型主体。

## 1. 数据模型层

### REQ-V3.10.2-001 实证保真度分级（Q-A）
- **语义**：候选 `empirical` dict 新增 `fidelity` 字段，枚举 `real_target | equivalent | mechanism`。
  - `real_target`：真实产品构建物/发布包/真实进程运行所得实测（缺省值，旧队列回填零行为变化）。
  - `equivalent`：目标依赖未物化等环境限制下，对 sink 语义的等价复现（复刻程序真实运行，但非目标本体）。
  - `mechanism`：机制级静态验证 + 局部小范围验证，不构成运行实测。
- **分级影响**：`fidelity=equivalent` 时 `evidence_grade=empirically_confirmed` 维持（gate ③ 判据不变），但报告「实证记录（R5）」行首渲染 `等价复现:` 前缀；`fidelity=mechanism` 不得升 `empirically_confirmed`（维持 edge_proven 上限）。
- **触发条件**：主代理回填 empirical 时填写；缺省按 real_target 处理。
- **消费者**：report 渲染器（行首前缀）、CVE 申报材料（真实构建物与复刻证据分列）、复跑 gate ③（判据不变但输出 fidelity 提示）。

### REQ-V3.10.2-002 裁决核验记录字段（Q-E）
- **语义**：`correction_record` 条目新增可选 `adjudication_verification` 数组——主代理采纳证伪者结论改判前，对证伪者承重前提主张逐条回源码核实的记录（每条含 `claim`（证伪者主张）、`verified`（核实结论 true/false）、`evidence_ref`（源码 file:line））。
- **触发条件**：主代理裁决降级（demote_to 或 1/2 采纳）时必填；无核实记录时门禁输出 warn。
- **消费者**：六门禁 warn 断言、复活波裁决审计（防「采纳未核实前提」再现）。

### REQ-V3.10.2-003 NEEDS_REVIEW 成因三档（Q-G）
- **语义**：NEEDS_REVIEW 成因从双分（保守裁决/证据不足）扩展为三分：新增 `环境受限`——环境无目标平台运行面（无设备/无运行库/依赖未物化）导致实证义务无法履行。
- **佐证注记**：成因=`环境受限` 且 evidence 含上游公开佐证（官方 issue 自认 / 同攻击类修复先例 / 已合并补丁未回移）时，附录 A 该行渲染「佐证注记」列（佐证来源摘要）；申报路径判定为「佐证材料路径」（非首发口径），终态不变。
- **触发条件**：主代理裁决 NEEDS_REVIEW 时三分成因必填其一。
- **消费者**：附录 A 渲染、CVE 申报资格预筛。

## 2. 机械层

### REQ-V3.10.2-004 workflow args fail-fast（Q-B）
- **语义**：`workflow_export.py` 导出的全部 workflow 脚本（verify/refutation/resurrect/shipped-config）在 agent 任务内首步校验输入有效性：默认契约键（如 `c.prompt`）或薄封装契约键（`c.taskFile`）至少其一存在且非空；缺失时**不向 agent 发任务**，直接返回结构化错误结果（`{id, verdict: "NEEDS_REVIEW", evidence: "workflow input missing: <key>"}` 或模式对应形态）。
- **collect 后验信号**：collect 时检测 journal 中「同 id 多 result 且内容 hash 各异」形态，输出 `journal_anomaly` 告警（提示幻觉 verdict 风险）。
- **触发条件**：导出脚本恒（校验为无副作用前置）；后验信号 collect 恒。
- **消费者**：派发方（错误落盘而非幻觉 verdict）、主代理 collect 输出。

### REQ-V3.10.2-005 R4 tracked 别名容错 + 空面分发（Q-C）
- **语义**：r4-collect 读取 finding 级与假说级 tracked 时，兼容 `surfaces` 别名形态（幂等合并，不覆盖 canonical 键）；「全量扫掠」语义的假说级 tracked（空 findings 假说声明扫掠面）不再拒收，覆盖率簿记按扫掠面计。
- **触发条件**：r4-collect 恒（幂等合并）。
- **消费者**：gate ⑦ 覆盖率簿记（消除 R4_TRACKED_MISSING 假失败）。

### REQ-V3.10.2-006 报告防覆盖（Q-D）
- **语义**：`--stage report` 检测目标报告已含主代理段落（第三节标题非占位符文本）时**拒绝重跑**（exit 非零 + 提示「主代理段落已存在，重跑将覆盖；如确需重生成请 --force」）；`--force` 显式重生成并 stderr 输出主代理段落丢失告警。
- **触发条件**：报告文件存在且含主代理段落时。
- **消费者**：主代理（报告定稿防丢失）。

### REQ-V3.10.2-007 NEEDS_REVIEW 重开命令（Q-H）
- **语义**：`batch_verify <project> --stage reopen --id <id>`：NEEDS_REVIEW 候选回 PENDING（保留 correction_record、needs_review_reason、refutation、resurrection_review 字段），并写 `reopen_reason`（blocker 解除依据，主代理必填）；重开后走标准验证流程（reopen 候选在 R3.5 入池规则上视为新候选对待）。
- **触发条件**：主代理判定 blocker 解除时显式调用。
- **消费者**：队列编排（NEEDS_REVIEW 升级通道）。

### REQ-V3.10.2-008 实证产物前缀检查（Q-L）
- **语义**：报告渲染时检查每候选 `empirical.harness` 路径，非 `.audit_results/` 前缀（相对）或项目根下（绝对）时，该行尾附 `[产物目录违规 warn]` 标记。
- **触发条件**：报告渲染恒。
- **消费者**：主代理（收尾修正目录违规）。

### REQ-V3.10.2-009 物化增量面重审提示（Q-K）
- **语义**：`--stage workflow-script` 的 `scope_changed` 输出扩展：物化目录（新出现/由空变非空）与 R1 面清单交叉，输出「受影响面重开建议」列表（该目录相关的树外面 + 依据 scope_dependent/物化标注）；主代理裁决后落盘 `scope_review` 记录（`{changed_dir, surfaces_reopened: [], decision: "reopen|keep", reason}`）至 `.audit_results/scope_review.jsonl`。
- **触发条件**：scope_changed=true 且 changed 非空时（建议级，不阻断）。
- **消费者**：主代理（裁决落盘供门禁审计追溯）。

## 3. 知识/契约层

### REQ-V3.10.2-010 平台信任模型清单（Q-F）
- **语义**：checklist_library 新增「平台信任模型」清单族，**按平台分派**（移动/桌面/web/嵌入内核/服务端部署等维度），每条为平台机制级条目（同设备异主体注入面、导出组件默认面、网络策略门、沙箱语义、平台鉴权中介），**不含任何具体项目 API 名**。信任边界几何判定（R2 筛选 / R3 步骤 3 / R3.5 证伪视角 / 主代理裁决）按目标平台绑定对应清单段，任务书注入；裁决层（主代理）在 trust_boundary 复核时对照清单逐条过。
- **触发条件**：目标含对应平台组件时（由 R1 测绘的平台信号判定）；无对应平台目标零行为变化。
- **消费者**：R2/R3/R3.5 任务书绑定、主代理裁决复核、门禁 r4_feedback 提示源。

### REQ-V3.10.2-011 补强逐条签收（Q-I）
- **语义**：r35-collect 落盘的 `strengthened`/`attribution_correction` 条目在报告渲染时默认附「（未复核）」标记；主代理对拟进入报告/申报材料的补强逐条签收（重演核验或回源码核实）后写 `strengthen_verified_by: main-agent`，渲染去标记。六门禁新增 warn 级：REACHABLE 候选存在未签收补强时不阻断但输出提示。
- **触发条件**：补强存在且被报告渲染引用时。
- **消费者**：报告渲染、申报材料（引用前必签收）。

### REQ-V3.10.2-012 构建依赖 CVE 对账注记（Q-J）
- **语义**：R1 context 输出增加依赖清单识别（按生态分派：依赖锁文件/构建清单中的 pinned 版本清单）；R3 步骤 1.5 扩展**可选步**：pinned 依赖的已知 CVE 对账（OSV/官方 advisory 查询，仅注记级——产出 `dependency_cve_notes` 列表，不改变候选裁决）；报告附录 B 增加「依赖风险注记」段渲染。
- **触发条件**：构建文件含 pinned 第三方依赖清单时（可选步，不强制）。
- **消费者**：报告附录 B、CVE 申报语境（攻击面完整性表述）。

### REQ-V3.10.2-013 实证防误伤样板（Q-M）
- **语义**：实证模板（parser_fuzz 及无匹配模板时现场构造指引）头部加入资源防护样板——按语言手册分派（进程限额/上限参数化/内存上限），模板 docstring 注明「复现安全性：无防护环境勿跑极值预设」。语言手册对应小节补样板代码。
- **触发条件**：模板生成时（按 lang 分派）。
- **消费者**：实证执行者（复现安全）。
