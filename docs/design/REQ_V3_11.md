# REQ_V3_11 — 系统需求（v3.11 设计缺陷修复）

> 对应设计文档：SYSTEM_DESIGN_V3_11.md。需求编号 REQ-V3.11-xxx。
> 每条含：语义 / 触发条件 / 消费者 / 案例支撑（三问已过，见设计文档 §3）。
> 本版不改变阶段骨架、六门禁判据语义、队列数据模型主体。

## 1. 数据模型层

### REQ-V3.11-001 攻击者主体层级字段（R-A）
- **语义**：candidate 新增 `attacker_tier` 枚举：
  - `same_process`：攻击者与目标同进程（宿主自身代码/嵌入内容未跨进程）
  - `same_device_cross_app`：同设备其他应用/进程经平台组件面注入（导出组件/意图参数/跨应用调用）
  - `system_broker`：经系统中介到达（系统服务绑定/用户授权中介/系统回调）
  - `remote`：网络可达内容（远程字节/远程会话）
- **推导规则**（缺省时）: reachability_type=DIRECT 且 trust_boundary=host_api → same_process;
  ACROSS_BOUNDARY 且输入源为平台组件注入 → same_device_cross_app（由 verifier evidence
  文本判定）; 输入源为网络内容 → remote; 无法判定 → 由主代理裁决。
- **触发条件**：R3 步骤 3 判定时 verifier 在 evidence 注明（结构字段 collect 落盘）；旧队列缺省推导。
- **消费者**：报告问题清单 tier 分列渲染、CVE 申报口径（CVSS 基线按 tier：same_device_cross_app
  取 AV:L 同设备、remote 取 AV:N）、主代理评级复核。

### REQ-V3.11-002 契约库条目 schema（R-B）
- **语义**：checklist_library 新增 `platform_api_contracts` 清单族（与 platform_trust_models 平级）：
  条目 `{id, platform, api_pattern, behavior, security_effect, probe, source}`——
  `api_pattern` 平台 API 机制描述（具体平台 API 类名仅进 probe 示例位），`behavior`
  该 API 对恶意输入的固有处理语义，`security_effect` 该行为对可达性判定的影响
  （阻断/放行/前提），`source` **必填**实证来源（审计追溯/平台文档），无来源条目拒收
  （防幻觉契约入库）。
- **首版条目来源**：从既有批次已实证的平台行为提炼（资产管理器条目查找、系统服务
  绑定中介、剪贴板前台限制、直缓冲分配保证），每条带批次追溯。
- **触发条件**：detect_platforms 信号驱动注入（与 v3.10.2 PTM 同管线）；零平台信号零注入。
- **消费者**：verifier/refuter/resurrect 三层 prompt（阻断/放行判定的知识基线）。

## 2. 供给面层

### REQ-V3.11-003 模板产物面登记（R-C）
- **语义**：R1 surface_map_domain 任务书新增指引段：仓库含模板/生成器/脚手架目录
  （路径信号：tmpl/template/scaffold/generator）时，该类文件是输入面的**实例化载体**——
  模板中声明的组件配置（导出属性/权限声明/入口注册）在产物生成时成为部署面的
  一部分；面登记时 entry_points 指向模板文件并标 `instantiated_artifact: true`。
- **R3 步骤 0.5 扩展**：构建包含性检查对模板文件按「模板 → 实例化产物」链判定
  （模板不随源码构建但随产物生成进入部署——存在性 = 产物生成链存在）。
- **触发条件**：仓库含模板/生成器目录（R1 路径信号检测）。
- **消费者**：R1 测绘、R3 步骤 0.5、阻断论证（「零导出组件」类论证必须核对模板产物）。

### REQ-V3.11-004 审计树差异声明（R-G）
- **语义**：R0 scope snapshot 扩展「构建差异声明」段：构建清单（依赖清单/构建脚本
  按生态分派）声明的依赖/生成物 vs 树内实际物化状态的差异表（依赖未物化/生成物
  缺失/外部构建面）；报告附录 B 渲染「审计树与部署物差异」段。
- **触发条件**：R0 scope snapshot 时检测构建清单（恒，产出差异表——空差异也落盘）。
- **消费者**：报告附录 B、「树外不可验证」类 drop 理由的可靠性声明、CVE 申报语境。

## 3. 判据/假说层

### REQ-V3.11-005 运行时版本条件检查项（R-D）
- **语义**：verifier 任务书步骤 4 阻断检测清单加「运行时版本条件」项：
  - 版本 API 级判断（版本宏/运行时能力检测）——同一代码路径在不同平台版本有
    不同攻击面（低版本无限制、高版本有门），阻断论证必须按**受影响版本区间**陈述；
  - 构建变体差异（调试/发布配置）——注入参数/调试面在发布构建被过滤的差异，
    作为前提维度写进 evidence。
- **形态**：提示级（无自动检测——语言习语过杂），evidence 渲染 + 主代理确认。
- **触发条件**：verifier 步骤 4 恒。
- **消费者**：verifier 证据、报告前提列、CVE 材料影响面陈述。

### REQ-V3.11-006 H4 初始化时序子项（R-E）
- **语义**：H4（跨进程信任边界破坏）检测要点加子项：「初始化时序注入面——启动
  参数/初始化前到达的输入在安全配置生效前被消费（启动窄窗/冷启动注入/初始化
  时序竞态）；输入到达时机与安全门生效时序的先后关系是判定前提」。
- **触发条件**：H4 恒（假说描述扩展，SKILL.md H4 表 + biz_hypothesis 模板同步）。
- **消费者**：R4 agent、gate ④。

### REQ-V3.11-007 逻辑镜像提示（R-F）
- **语义**：R1 merge 阶段输出 `mirror_candidates` 提示：不同 surface 语义相似
  （name/taint_channels 关键词重叠）且 lang 不同的面组（不自动组族——主代理
  裁决是否作为逻辑镜像族登记）；R2 假设生成任务书加「逻辑镜像枚举」条款：
  同逻辑面在目标的多语言实现是否全部覆盖（sink 同构性逐一核实）。
- **触发条件**：language_inventory ≥2 时 merge 输出提示。
- **消费者**：主代理（merge 复核）、R2 假设生成。

## 4. 明确不做（义务棘轮防护）

- 不改 reachability_type 枚举、不加新门禁、不自动组族、不做运行时版本自动检测
  （详见设计文档 §4）。
- 契约库条目无 source 拒收（防幻觉契约）——本版唯一「拒收」级校验，仅约束新清单族。
