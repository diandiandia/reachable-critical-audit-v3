## 1. 十大问题域与 V3.1 对策

### P-A 签名库对多语言/成熟框架零区分度 → 签名分层 + LLM 主路径制度化

**现象（lesson 证据）**：PS 7/7 签名零覆盖（§9.1）、Shell 零覆盖（§12.1）、C# 反序列化族零覆盖（§13.1）、
Python/TS/PHP/Kotlin 通用 regex 命中数百至数千但 keep 率 0%（§14.1/15.1/17.3/19.1）。
战役 17 项目 sink_discovery_rate 普遍 0%，false_negative_risk 普遍 100%——**但零漏报**，
因为 LLM 假设路径独立产出了全部真实发现。

**V3.1 设计变更**：

1. **签名库三层重构**（`signature_library.json` v3.1 schema）：
   - **L1 通用危险词**（append/encode/join/::class 类）：降权为"阅读提示"，**不再生成假设**（§14.1 退役先例制度化）；
   - **L2 语言词族**（15 语言 × 真实 sink 习语，从战役回填：PowerShell `[ScriptBlock]::Create`/dot-source、Shell `trap/eval/curl|sh`、C# `TypeNameHandling/BindToType/Assembly.Load`、Python `pickle.loads/get_host/asgi read_body`、TS `socket.on('data')`/multer 无 limits、Kotlin `receive/readRemaining` 等——每族带已知实例）；
   - **L3 框架语义族**（per-framework 签名，含 runtime_prereq 字段：如 ReDoS 类签名注明"Ruby≥3.2 Oniguruma 线性化，先验下调"（§24.3）；反序列化 gate 矩阵 × 读/写端（§13.2））。
2. **LLM 假设生成为正式主路径**：R2 流程重排为「主代理（或限时 agent）基于 surface 图生成假设 → 签名命中作佐证提示」；签名的角色从 V3 的"提示器"再降半级为"佐证器"——**假设不依赖签名存在**（战役 8 语言已证明该路径独立可用）。
3. **签名贡献度度量**：每假设记录 `sources: ["LLM"|"SIG-xxx"]`；连续 2 批次贡献度 <10% 的签名自动退役入 `retired_signatures`（§14.1 先例的自动化）。

**为什么能解决**：该问题域的根因是"用静态词表表达语言习语"这个范式本身的覆盖上限——15 语言的
sink 习语无穷而词表有限。v3.1 不试图补全词表（V3 也承认规则是提示器），而是把战役已验证的事实
（LLM 假设路径 8 语言零漏报）提升为流程正式路径：签名从"覆盖义务"中彻底解放，盲区不再等于漏报；
贡献度度量给签名库装上修剪反馈环，防止噪音复燃。

### P-B R1 测绘证据质量（漂移/幻觉/失控/签收缺口）→ 校验器升级 + agent 预算约束

**现象**：行号漂移从 AWStats 3 处（§1.2）恶化到 lighttpd 的 ±45 + 细节臆造（§22.1）；
WP 假设 agent 失控 2.5h（§17.1）、Dubbo R1 总耗时 2h+（§18.6）；空域被拒收（§9.2）、
schema 违约漏字段（§9.3）、主代理修复脚本二次污染（§9.5）、幻觉行号（§12.2）。

**V3.1 设计变更**：

1. **validate 器 v3.1**（`surface_mapper.py`）：
   - 双态匹配（原始 snippet + `snippet_unescaped` 变体任一命中即过，§1.1）+ 超短行过滤（`len(first_line)>=10`，§1.2）；
   - 修复窗口 ±30→**±80**，`suggested_line` + **`paraphrased: true` 标记**（首行不命中且窗口无匹配时标记而非静默，§22.1）；
   - 相对路径自动解析（非绝对路径 → project_root 拼接，§24.7/§10.1 教训）；
   - 空域签收（`empty_domain_reason` + `reviewed_by`，§9.2）、逐字段断言 + `confidence_added_by` 审计（§9.3）。
2. **agent 预算约束**（规模自适应档位）：<100 文件 → 2 agents 无限时（§24.7）；100-500 → 4 agents 无限时（§20.5 舒适区）；>500 → 4 agents + **45 分钟硬时限 + 中间产物每 10 分钟落盘**（§17.1/18.6 失控判据=超时+无落盘）。
3. **主代理修复器幂等契约**：修复脚本 best-match 必须非空否则回滚；已匹配 entry 不重标 `evidence_rewritten_by`（§9.5）。

**为什么能解决**：证据质量问题的三条根因各有对应机制——(a) 校验器语义与源码形态不匹配（字面实体、
超短行、相对路径、paraphrase）→ 校验器按实测形态升级；(b) agent 无预算导致的扩张失控 → 硬时限 +
落盘判据（失控被机械检出而非主代理观察）；(c) 修复动作无回滚 → 幂等契约。三条都是把战役中
主代理的"手工兜底"变成工具的"默认行为"。

### P-C R2 假设生成的持久化缺口 → schema 强制 + 机器校验

**现象**：surface 归属合并丢失 3 次重现（§9.6/12.6，门禁⑦误报）；keep/drop 决定未落盘（§16.7）；
退化候选（doc block 当 sink，§23.7）；防御签收类假设占 R3 队列（§14.2）；复审计凭 v2 记忆而非
终稿导致假设评级错误（§22.2）；JSON 裸引号第 4 次重现（§3/15.8）；prompt 截断（§10.3）。

**V3.1 设计变更**：

1. **假设 schema 强制**：`surface_ids: []` 数组（非单值，§9.6/12.6/16.7 三次重现的根修）；
   入队前主代理对锚点行做 Read 验证（非文档/注释行，§23.7）；`boundary-confirmation` 类
   （防御已 Read 验证）单独归类**不占 R3 队列**（§14.2）。
2. **r2_filter 全量落盘**：keep/drop 均写 `dropped_by + reason`（§16.7）——门禁⑦覆盖率簿记的
   证据基础。
3. **复审计上下文注入**：R2 任务书自动附旧审计**终稿**摘要（report.json 的 reachable/needs_review
   清单），禁止凭记忆（§22.2）。
4. **collect 全家族 lenient load + 单遍转义修复**（`evidence_ledger` 内建，§3.1-3.3 的振荡问题以
   "单遍扫描 + `\u` 仅当后接 4hex"规则固化）。

**为什么能解决**：该域所有缺口的共性是"信息存在于 agent 回复文本中但未进入结构化字段"——
靠主代理事后语义重建，因此不可靠且每次重现。v3.1 把字段义务写进 schema 与任务书（机器校验
拒收缺失字段），把"事后重建"从主流程中删除。

### P-D R3 verifier 系统性乐观偏差（最大问题域）→ 前提优先 + 家族检查清单 + 自证伪提示

**现象（lesson 证据）**：15 语言战役 R3.5 平均拦截 ~50%——verifier 判的 REACHABLE 一半被证伪。
典型盲区：承重前提未验证（§17.10 严格相等门控漏看）、分支可达性未验证（§19.5 边真实≠分支可达）、
getter 控制流推断错误（§16.9）、"无上限"=未找到上限（§21.2）、机制真≠危害真（§20.1）、
引擎流式 vs 应用物化（§20.2/23.1）、注入原语未枚举（§22.4）、动态注册防御漏查（§17.4-17.5）、
同族监听点未枚举（§15.5）、dead-cache（§16.13）。

**V3.1 设计变更**：

1. **verifier 任务书重构为「步骤 0 + 家族清单驱动」**：
   - **步骤 0：承重前提验证**——先 grep 一句话能证实/证伪的假设前提，断裂立即终止（§17.10 直接制度化）；
   - 每候选按语义家族**自动绑定检查清单**（从 `checklist_library.json` 带出，见下）。
2. **检查清单库（新组件 `checklist_library.json`）**：把 15 语言战役的 20+ 条"证伪者攻击面"固化为
   verifier 强制自查项。首版回填：
   | 清单 id | 内容 | 来源 |
   |---|---|---|
   | CK-WS-MATERIALIZE | WS/分片类：框架是否物化整条消息（逐帧产/1:1 透传/逐项交付） | §20.2/23.1 |
   | CK-UNBOUNDED-HOPS | "无上限"声称：枚举队列/通道每一跳容量常量 | §21.2 |
   | CK-INJECT-PRIMITIVES | 注入类：逐一枚举换行/NUL/名污染三原语并验证阻断 | §22.4 |
   | CK-HEADER-RESIDUAL | 头注入四级残余：CRLF→quote→全 C0→NUL | §24.5 |
   | CK-DEFAULT-3LAYER | 默认值三层语义：代码默认/模块加载/部署前提，三层全开才算默认 | §22.3/23.2 |
   | CK-ENGINE-MATRIX | 多引擎框架：REACHABLE 须在文档默认引擎成立 | §19.8 |
   | CK-DYNAMIC-DEFENSE | 防御验证须搜索全部动态注册点（init 回调内注册） | §17.4-17.5 |
   | CK-SIBLING-LISTENERS | 异常处理链：枚举全部同族监听点 | §15.5 |
   | CK-DEAD-CACHE | storage/缓存写点：查 key 注册存在性 | §16.13 |
   | CK-COMMENTED-GUARD | 主动 grep 被注释的安全守卫行 | §22.6 |
   | CK-DUAL-PARSER | CWE-436：枚举两个安全判定解析器并证明分歧 | §20.3 |
   | CK-HOST-AUTH-CONSISTENCY | absolute-form 族：查 Host↔authority 一致性校验 | §20.4 |
   | CK-RUNTIME-RE | ReDoS：先问运行时版本是否线性化（Ruby 3.2+/net8） | §24.3/13.4 |
3. **自证伪提示（前置 R3.5 攻击面）**：每个 REACHABLE 候选的任务书自动附「最可能的 2 条证伪论据
   （按先例库匹配）」要求 verifier 自查——把证伪者 8 批次积累的攻击面变成 verifier 的预检项。
   目标：R3.5 拦截率从 50% 收敛到 30% 以下（拦截率下降在此处是**好**指标，说明 R3 质量上升）。
4. **verifier 实证白名单**：任务书显式允许轻量探针（ruby -Ilib+Rack::MockRequest、python venv、
   cargo test 单文件、真实 jar+最小输入等），实证标记强制结构化落 `empirical` 字段，
   collect 自动从 evidence 提取实证标记（§14.5/15.2/24.8/18.5）。

**为什么能解决**：verifier 乐观偏差的根因是**假设惯性**（§17.10 原话："沿假设惯性向前推，
未回头验证承重前提"）+ 无结构化反证输入。v3.1 的三层机制逐一拆解：步骤 0 打断惯性；
家族清单把 20+ 个已发生的盲区变成强制自查项（盲区发生过一次就不会再以同形态漏过）；
自证伪提示让 R3 在提交 R3.5 前先被攻击一遍。这三层共同把"verifier 乐观 → 证伪者兜底"
的串行容错结构改为"verifier 内置反证"的收敛结构。

### P-E R3.5 证伪者机制 → 实证工具箱模板 + 结构化修正字段

**现象**：证伪者已自然演化出实证工具箱——百万级差分对拍（§21.1）、真实 jar 畸形矩阵（§19.4）、
标准基础设施实测（§16.10）、真实 WP_Hook 复测（§17.9）——但均为个案行为；另有补强向量（§13.6）、
归因更正（§12.5）、半程输出误采信（§5）、args 结构错误（§15.7）等机制缺陷。

**V3.1 设计变更**（`workflow_refutation` 模板 v3.1）：

1. **证伪者实证工具箱模板**：refuter 任务书按声称类别附标准动作——区间/边界类 → 参照模型 +
   随机对拍（§21.1）；解析类 → 真实构件 + 畸形输入矩阵 + 触发计数（§19.4）；代理/解析分歧类 →
   标准基础设施配置片段实测（§16.10）。
2. **结构化修正字段**：`strengthened`（补强向量，§13.6）、`attribution_correction`（归因更正，§12.5）、
   `note`（残余保留意见，§12.4）进入 refutation 结果 schema。
3. **机制修正**：resume 必须携带与首跑一致的 args（§5）；只采信 schema-validated 最终返回，
   半程输出作废（§5）；同 id 多 entry 合并投票（§15.7）；出队条件排除已复核（§12.3）。

**为什么能解决**：证伪者的高价值来自"独立实验"而非"推理"——把三种最有效的实验形态模板化后，
每次复核自动获得 8 批次积累的证伪深度；机制修正消除工作流层的误判源（半程输出、投票语义破碎）。

### P-F 裁决先例库（v3.1 最大新增组件）→ precedent_library.json + 一致性断言器

**现象**：20+ 条裁决先例跨 15 语言反复引用——能力支配 6 例（§11/12.4/13.8/16.11/18.4）、
by-design（§12.4/19.6）、矩阵保留（§14.7/17.6）、同族一致性（§18.3/23.4）、三层默认开启（§22.3/23.2）、
文档化有意设计（§24.2）、受害方可触发性（§24.1）、危害被前提吸收（§18.4）、开发专用面（§14.4）、
引擎矩阵（§19.8）、gate 评级规则（§23.5）、同事实双口径（§24.9/16.12）。当前全部存在于 lessons
文本中，靠主代理记忆调用——而记忆已被证明会漂移（§22.2 凭草稿记忆评级错误）。

**V3.1 设计变更**：

1. **`precedent_library.json`**（新组件，D-COMP-09）。每条先例：
   ```json
   {
     "id": "PREC-CAPABILITY-001",
     "name": "能力支配",
     "criterion": "攻击者触发该 sink 所必须持有的前提，本身已蕴含更强能力（如会话内任意代码执行）→ 零能力增量 → 降级 NEEDS_REVIEW",
     "counterexample": "隐式行为面（repo 内容即输入，无需攻击者运行代码）不适用能力支配（§11 教训）",
     "applicability_scope": "仅适用于『攻击者已运行代码』前提类；不适用于零代码执行前提的隐式面",
     "applications": ["Pester CAND-008", "ohmyzsh CAND-001/014", "Json.NET CAND-006", "Vapor CAND-013", "Dubbo CAND-004"],
     "source_lessons": ["W6 §11", "W6 §12.4", "W6 §13.8", "W6 §16.11", "W6 §18.4"]
   }
   ```
   首版回填 ~14 条（含上表全部 + Host 采信族裁决树 §23.4+§24.1 四维判据、矩阵保留、同族一致性等）。
   **每条必须带 `applicability_scope` 与 `counterexample`**——§11 的核心教训是"论据的适用前提范围"
   必须先于论据本身判定。
2. **一致性断言器**（evidence_ledger 扩展）：队列落盘前自动扫描同 sink 家族候选的 verdict
   可比性，不可比 → 告警（§18.3 从"证伪者武器"升级为"系统断言"）。同事实双口径映射
   （候选 NEEDS_REVIEW ↔ R4 confirmed gap）在报告模板强制呈现（§24.9/16.12）。
3. **裁决产出 schema 化**：`correction_record` 字段族（demoted_by/date/reason/precedent_ids）
   在战役中已形成惯例，v3.1 写入 VERDICT_SCHEMA。

**为什么能解决**：先例的当前载体（lessons 文本）有两个缺陷——检索靠主代理记忆（漂移风险，
§22.2 已发生一次实际错误）且应用靠主观判断（同族一致在 §18.3 是证伪者武器、§23.4 是主代理裁定，
两次都对但依赖人）。机器化后：(a) 裁决可复现——同一前提形态在 15 语言给出同一裁决；
(b) 一致性从"事后抽查"变"事前断言"；(c) 每个新项目自动继承 17 项目的裁决经验，
而不是继承审计者的记忆。

### P-G 实证 harness 体系 → 语言工具链手册 + 范围分级 + 环境陷阱自检

**现象**：实证失败成本几乎全部来自可枚举陷阱——swift 工具链代际/路径遮蔽（§16.1-2）、
stale 进程端口复用致两轮全零数据（§16.5）、`$!` 子 shell 陷阱（§16.6）、响应体不可达（§16.3）、
JDK 25 Inflater 语义变更（§19.3）、cargo PATH/dev-dep 可见性/编译器建议误导三连（§23.3）、
网络阻断（§21.4）、语义前提假阴性（§13.7）、多 member 行为维度缺失（§23.8）；另有范围纪律
（机制级 vs E2E，§17.7；函数体级 scope，§15.6）、claim 诚实性（§13.9）、运行时版本影响利用性（§13.4）。

**V3.1 设计变更**（`harness_runner` v3.1）：

1. **语言工具链手册（新资产 `harness_manuals/<lang>.md` × 15）**：每语言一页 =
   {探测命令（find 全盘工具链核版本，§16.2）、版本精确记录义务（§16.1）、常见陷阱清单、
   阳性模式（真实解码器最小输入 §18.5 / verbatim 提取+真实 jar §19.2 / PHP 最小环境 §17.8 /
   Ruby -Ilib+MockRequest §24.8 / cargo 单文件 test §23.3）、网络依赖清单（§21.4）}。
2. **实证范围分级强制**：`scope ∈ {mechanism, function_body, full_chain, e2e}` + `scope_note` 必填；
   **机制级实证只能支撑 edge_proven 升级，不得直接升 empirically_confirmed**（§17.7/15.6 写死为规则）；
   多 member/多维度实证要求（解压放大类必须单 chunk ratio + 多 member 行为两维度，§23.8）。
3. **环境陷阱自检清单**（harness 启动前必跑）：stale 进程清理 + diag 路由自检（§16.5）、
   daemon 采样线程（§16.3）、env 传播验证（§16.6）、测量点放服务端（§16.3-4）、
   语义前提先验证（0ms 结果先怀疑前提，§13.7）。
4. **对照矩阵实证模式**：默认配置拒绝 + 弱化配置接受 的对照实验入模板（§24.4）。
5. **源事实级降级规则**：网络阻断 → `source_fact` + blocker 记录；哨兵值/算术类主张按
   §17.7/§21.3 接受源事实级（etcd CAND-002、actix CAND-006 先例）；**claim_type 先于实证定类，
   不得因实证成本降级 claim**（§13.9）。

**为什么能解决**：实证的成本结构是"陷阱清单重复支付"——vapor 两轮全零的根因（stale 进程）
与 actix 编译三连的根因（PATH/dev-dep）完全不同但同属清单条目。手册化把踩坑成本从
"每项目重付一遍"降为"一次性入册"；范围分级规则消灭了证据等级虚标（§17.7 被证伪者揪出
的 empirically_confirmed 注水问题）；对照矩阵把最强的实证形态（§24.4 被评价"强一个量级"）
从个案变标准。

### P-H R4 前置化与 H7 默认值盘点模板 → 成熟度判定 + 标准化盘点

**现象**：R4 产率三次反超 R3（§23.6/24.6 + etcd/akka 同向）；H7 默认值家族收割效果显著
（ktor 9 findings §19.7、sinatra 4 Medium §24.6）；新家族持续涌现（GIT_CONFIG env §12.7、
reply 通道族 §15.4）；R4/R3.5 判定框架不一致（§16.12）；R4 异常路径描述被实证纠正（§13.5）。

**V3.1 设计变更**：

1. **成熟度判定前置（R0）**：按项目形态（framework / library / infra / app）+ 防御默认面观察
   判 `maturity`。mature 项目：**R4 与 R3 并行启动**，H1/H7 深度上调；immature 项目保持串行。
2. **H7 标准化为「默认值全表模板」**：产出 = 每默认值 × {三层语义（§22.3）、哨兵语义
   （查依赖库对 MAX/-1/0 的处理，§21.3）、数值红旗（MAX_VALUE/-1/0 三值即红旗，§19.7）、
   文档声明（README/CHANGELOG 中的"有意"声明，§24.2）、正向默认确认（防御完整项的显式输出，
   §20.6）}。对照模板随每批次回填（新增"与已知防御完整框架对照"维度，如 sinatra↔actix 上限体系对照）。
3. **H1-H7 检查清单动态回填**：每批次新家族自动入清单（GIT_CONFIG env → H4 清单；reply 通道族 → H4；
   检查点晚于累积点 → H1 清单第一条 §14.3）。
4. **R4 finding schema**：`tracked_surfaces` 强制（§4/9.7）、`r3_link`（与候选裁决的引用，§16.12）、
   `empirical_result` + `mechanism_correction`（§13.5）。

**为什么能解决**：成熟框架的 R3 天花板是 Low 级硬化缺口（sinatra 2 REACHABLE 全 Low）而 R4
抓到 High（actix Payload 无界）——资源错配在 v3 中靠主代理事后补 R4 深度。前置判定把 R4
从"兜底网"升级为成熟项目的"主攻面"；H7 模板化把最产出的假说从"agent 自由发挥"变成
"逐项机器盘点"，产出可预期、可跨项目对照。

### P-I 工程健壮性 → workflow 规范条款 + lenient 层内建

**现象**：`${}` 顶层插值致 workflow 双波全崩（§17.2）、args 截断（§10.3）、journal result/value
字段不统一（§10.4）、JSON 非法转义修复振荡（§3.1-3.3）、裸引号 4 次重现（§15.8）、set 序列化 bug
（§8）、resume 缺 args（§5）、出队重复（§12.3）、CLI 子命令无测试（§8）。

**V3.1 设计变更**：

1. **workflow 脚本规范条款**（写入 SKILL 与模板注释）：顶层 const 模板字面量禁 `${}` 插值
   （§17.2）；resume 必须携带与首跑一致 args 且脚本内 `args ?? {}` 防御（§5）；args 必须从
   落盘文件整读整传，禁止复制预览截断（§10.3）；journal 提取兼容 result/value 双字段（§10.4）。
2. **collect 全家族 lenient load + 单遍转义修复器**内建（§3.1-3.3 算法：`\` 后接合法转义
   原样保留否则双写并跳下一字符；`\u` 仅后接 4hex 合法——一次扫描不重审，杜绝振荡）。
3. **CLI 序列化薄测试**：main() 各子命令必须有走通序列化路径的测试（§8 教训：生成逻辑与
   打印分离）。
4. **出队条件**：refutation pool 排除已复核候选（§12.3）。

**为什么能解决**：该域全是"同构 bug 重复发生"类——每个 bug 都已在战役中发生并手工修复，
但修复只存在于某次会话的临时脚本里。v3.1 把它们升为**规范条款**（对工作流模板的静态约束）、
**内建函数**（lenient 修复器不再依赖主代理临时脚本）、**测试用例**（回归防线）三层。

### P-J 指标与门禁 → 门禁修正 + 覆盖簿记机器化

**现象**：R0 smoke 全 skipped 误伤（§7）；empirical 标记未结构化致门禁③假 FAIL（§15.2）；
R4 findings 同受 gate ③ 约束（§18.9）；覆盖率簿记 4 次重现（tracked_surfaces/surface_ids）；
claim 诚实性（§13.9）；同事实映射表（§24.9）。

**V3.1 设计变更**：

1. **R0 门禁条件修正**：`hit_rate < 1.0 AND testable > 0 → 阻止`（§7）。
2. **gate ③ 扩展**：实证类声称（crash/panic/oom/unbounded/xss/protocol_dos）的强制实证
   义务**同覆盖 R4 confirmed findings**（§18.9）；claim_type 按攻击影响定类先于实证（§13.9）；
   哨兵值/算术类按源事实级规则豁免（§17.7/21.3）。
3. **覆盖率簿记机器化**：只认 `SURF-` 前缀 id（§9.7）；R4 的 `tracked_surfaces` + 假设的
   `surface_ids` 数组直接驱动门禁⑦统计（§4/9.6/12.6/16.7 四次重现的根修）。
4. **报告模板**：NEEDS_REVIEW ↔ R4 finding 同事实映射表（§24.9）；条件式 REACHABLE 前提逐条列出
   （§6）；verdict 修正记录显式列出（既有）。

**为什么能解决**：门禁的权威来自"误报为零"——§7 与 §15.2 两次误伤都在侵蚀这个权威。
修正后的门禁只拦真实违规；簿记机器化让门禁⑦从"主代理语义重建"（四次重现）变成 schema
驱动的机械统计。

## 7. 关键设计决策与权衡

1. **自证伪提示可能造成 verifier 过度保守**（把强 finding 也自我降级）→ 缓解：自证伪提示只注入"先例库匹配到的论据"，且 verifier 输出分离"自查结论"与"裁决结论"，主代理裁决只看后者。
2. **先例库可能僵化裁决**（新前提形态被旧先例误配）→ 缓解：每条先例带 `applicability_scope` + `counterexample`；先例匹配失败不阻塞裁决，主代理可自由裁量并回填新先例（库随审计进化，与 V3 的 known_instances 同哲学）。
3. **R4 并行化增加 token 成本** → 缓解：仅 mature 项目并行；immature 保持串行（战役数据：并行窗口约省 30% 墙钟）。
4. **L1 签名退役可能漏掉"提示价值"** → 缓解：L1 不生成假设但仍注入 verifier 任务书上下文（阅读提示），贡献度只统计假设层。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 先例库/清单库本身成为新"规则库"（僵化盲区） | 库是裁决依据而非发现依据；发现仍靠 LLM；每条带 counterexample；审计后回填自进化 |
| 自证伪提示造成真发现被 verifier 自我降级 | 分离自查/裁决两结论；主代理终裁不采信自查结论 |
| 门禁③扩展至 R4 使实证负担翻倍 | 源事实级豁免规则（哨兵/算术类）+ 语言手册降低单次成本 |
| 资产回填工作量（14 先例 + 13 清单 + 15 手册） | 全部从现有 lessons 文本机械转写，无新研究 |
