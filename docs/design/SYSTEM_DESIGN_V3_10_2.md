## 2. 修复策略（13 项 REQ，详见 REQ_V3_10_2.md）

1. **实证保真度三档**（Q-A）：`empirical.fidelity` 枚举 `real_target | equivalent | mechanism`（缺省 `real_target` 兼容旧队列）；gate ③ 判据不变（声称类 REACHABLE 需 `empirically_confirmed`），但 `equivalent` 档在报告渲染与 cover 申报材料时强制标注「等价复现」——真实构建物与复刻证据分列，不混级申报
2. **workflow args fail-fast**（Q-B）：导出脚本（含薄封装范式文档）agent 任务内首步校验必需输入键，缺失返回结构化错误 verdict（id + evidence 说明输入缺失）而非把 "undefined" 交给 agent；journal 后验信号（同 id 多 result 且内容 hash 各异）加入 collect 告警
3. **R4 tracked 别名容错 + 空面分发**（Q-C）：r4-collect 读取 `surfaces` 别名形态（幂等合并）；空 findings 假说允许「全量扫掠」语义的假说级 tracked 直填（r4-collect 不再拒收，覆盖率簿记按扫掠面计）
4. **报告防覆盖**（Q-D）：`--stage report` 检测已存在主代理段落（非占位符）时拒绝重跑，`--force` 显式覆盖并输出告警（主代理段落丢失警告）
5. **裁决独立性核验义务**（Q-E）：主代理采纳任一证伪者结论改判（demote / 1/2 采纳）前，必须对证伪者的承重前提主张逐条回源码核实，核实记录写入 `correction_record.adjudication_verification`；六门禁新增 warn 级断言（demote 无核实记录 → 提示，不阻断——放行方向已由复活波兜底）
6. **平台信任模型清单**（Q-F）：checklist_library 新增「平台信任模型」清单族（按平台分派：移动/桌面/web/嵌入内核等，键为平台机制——导出组件+意图参数注入、同设备异主体、网络策略门、沙箱语义——非具体项目 API）；信任边界几何判定步骤（R2/R3/R3.5/裁决）绑定目标平台清单
7. **环境受限佐证注记**（Q-G）：NEEDS_REVIEW 成因扩展第三档 `环境受限`（现有两档：保守裁决/证据不足）；`环境受限` 且 evidence 含上游公开佐证（官方 issue 自认/同攻击类修复先例）时，报告附录 A 渲染「佐证注记」行——申报走佐证材料路径，终态不变
8. **NEEDS_REVIEW 重开**（Q-H）：`batch_verify --stage reopen <id>`：NEEDS_REVIEW 候选回 PENDING（保留 correction_record 与 needs_review_reason），重开需主代理写 reopen_reason（blocker 解除依据）
9. **补强逐条签收**（Q-I）：r35-collect 落盘的 strengthened/attribution_correction 默认渲染「（未复核）」标记；主代理签收写 `strengthen_verified_by` 后去标记；门禁 warn 级（未签收补强进入申报材料时提示）
10. **构建依赖 CVE 对账注记**（Q-J）：R1 context 输出依赖清单文件识别（按生态分派）；R3 步骤 1.5 扩展可选步——pinned 依赖的已知 CVE 对账（OSV/官方 advisory），产出「依赖风险注记」进报告附录 B（注记级，不改变候选裁决）
11. **物化增量面重审提示**（Q-K）：scope_changed 输出扩展「受影响面重开建议」（物化目录对应的树外面清单）；主代理裁决后落盘 `scope_review` 记录（重开或维持，附理由）
12. **实证产物前缀检查**（Q-L）：报告渲染时检查 empirical.harness 路径前缀，非 `.audit_results/` 前缀输出 warn 行
13. **实证防误伤样板**（Q-M）：parser_fuzz 等模板头部加资源防护样板（按语言手册分派：限额/上限参数化），模板 docstring 注明复现安全性
