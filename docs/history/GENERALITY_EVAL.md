# v3 通用性评估：新系统是否满足"通用型代码审计 skill"的初衷

> **日期**：2026-08-16（首轮开发完成后评估）
> **初衷拆解**（v1/v2 的设计目标 + 历次审计教训）：
> ① 语言通用（不限于 15 种预设）② 项目类型通用（Web 框架/系统软件/沙箱/工具都审）
> ③ 零配置自治（无 API Key、无人工规则维护）④ 结论可靠（无幻觉、可问责）
> ⑤ 随审计进化（审计越多能力越强）
> **评估方法**：逐维度对照 v2.1 实证缺陷与 v3 设计/实现，标注"达成/部分达成/未达成/未验证"。

## 1. 逐维度评分卡

|---|---|---|---|---|

## 2. 剩余通用性缺口（诚实清单）

### 2.1 语法族盲区（①的边界）
`signature_matcher` 的 ProjectIndex 与窗口展开基于 C 系/脚本系语法正则
（`fn|def|func|function|sub` + `name\(`）。以下语言族会失效：
- Lisp 系（`(defun f (x) ...)`）、Forth/PostScript、OCaml/F#（`let f x =`）、
  SQL 存储过程、汇编、声明式 DSL（terraform/HCL）
- 影响：函数索引为空 → 窗口只有第 0 层 → 签名匹配漏长链 sink
- 严重性：中（这些语言族本就不在 v2.1 覆盖内，v3 至少第 0 层仍可用）
- 补强：per-语言族函数识别适配器（C-like/script/lisp/ml/declarative 5 族），
  或语言未知时退化为"行级窗口"（放弃函数索引，纯 file 级扫描）

### 2.2 项目类型假说盲区（②的边界）
- surface 4 域（network/data/process/storage）与 H1-H7 假说覆盖：
  内存破坏/信任边界/鉴权/多租户——**Web 服务端与系统软件为主**
- 未覆盖的项目类型与缺陷族：密码学误用（CWE-327/338 侧信道）、编译器/解析器
  生成器（语法混淆/优化缺陷）、区块链共识、固件/驱动（DMA/IOMMU）、
  构建系统与供应链（依赖混淆）、机器学习系统（模型注入）
- 严重性：中高——"通用"的最薄弱维度
- 补强：surface 域与 H 假说改为**可注册清单**（registry），与 known_instances
  同机制回填：每次审计遇到新项目类型/新缺陷族，沉淀为新域/新假说

### 2.3 实证模板的手工性（④的边界）
- harness 模板 4 个，全部手工沉淀于实战。全新 claim 类型（如"共识协议分叉"、
  "缓存侧信道"）需要现场构造 harness
- 严重性：低——采样协议（RSS/存活/速率确认）本身通用，模板是积累物
- 补强：模板带"家族签名"字段，与 signature_lib 的 empirical_harness 双向绑定，
  签名新增时强制评审是否需要配套 harness

### 2.4 实战未验证（全部维度的最大风险）
- 48 单测 + 1 集成测试是**合成场景**；v3 尚未在任何真实项目上跑过
- SWR-091（sinatra/lighttpd/actix 回归对照）未执行——"通用性"目前是设计级主张
- 严重性：**高**——这是下一步唯一真正重要的验证

### 2.5 小项目成本（⑥的边界）
- 4 域测绘 × 4 agent + 假设筛选对 <500 行脚本偏重
- 补强：按规模自适应（SWR-V3 已有 R4 档位先例），小项目 1 域合并测绘

## 3. 结论

**满足初衷的程度：核心初衷达成（约 80%），结构性优于 v2.1，但"通用"仍有两类诚实边界：**

1. **达成（结构性）**：语言通用（语义签名+LLM 主引擎彻底绕开"规则库×语言"组合爆炸）、
   零配置、结论可靠性机制、自进化机制——这四项是 v2.1 的根因缺陷，v3 均已从架构层解决。
2. **部分达成**：项目类型通用——域与假说清单仍是封闭枚举且偏 Web-内存家族；
   语法族盲区——函数识别有 C 系假设。
3. **未验证**：全部通用性主张尚未经实战审计检验（SWR-091 是锚点）。

**补强优先级**：
1. **SWR-091 回归对照（最高）**——用 sinatra（脚本系、Web）、lighttpd（C、服务端）、
   actix（Rust、框架）三个已审计项目跑 v3 全流程，对照已知结论；
   通过 = 通用性主张获得实证锚点；失败 = 暴露测绘/签名/分级的真实缺陷
2. 域与假说注册化（解决 2.2）
3. 语法族适配层（解决 2.1）
4. 小项目规模档位（解决 2.5）
